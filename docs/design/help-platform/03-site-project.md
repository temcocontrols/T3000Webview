# 03 — The site project: `docfx.json`, `toc.yml`, URLs

*Covers: Layer 1–2, Content Organization, Version Management (URL part).*

The site project is two generated files plus one hand-written page:

```
docs/
├─ docfx.json     ← generated from docs/help/registry.json   (never hand-edited)
├─ toc.yml        ← generated (the top navigation bar)
├─ index.md       ← hand-written homepage (landing layout)
├─ toc.yml        ← per area, generated:  t3000/toc.yml  legacy/toc.yml  design/toc.yml
└─ templates/t3000/   ← hand-written template layer (see 04-template.md)
```

`docfx.json` lives in `docs/` **on purpose**: every relative path in DocFX is resolved against the
directory that contains `docfx.json`, so putting it there makes `t3000/quick-start/overview.md` the
natural spelling and keeps `~/` links inside the corpus.

---

## 1. `docs/docfx.json`

Generated by `scripts/docs-registry.mjs` (`npm run docs:registry`) and verified with `--check` in CI. The
shape below is the real one for this repo; comments are for this document only.

```jsonc
{
  "build": {
    "content": [
      { "files": ["t3000/**/*.md"], "src": ".", "dest": "." },
      { "files": ["legacy/**/*.md"], "src": ".", "dest": "." },
      { "files": ["design/**/*.md"], "src": ".", "dest": "." },
      { "files": ["help/*.md"], "src": ".", "dest": "." },
      { "files": ["index.md"] }
    ],
    "resource": [
      { "files": ["**/*.{png,jpg,jpeg,gif,svg,webp,ico}", "**/*.pdf", "**/*.zip"] }
    ],
    "dest": "_site",
    "template": ["default", "modern", "templates/t3000"],
    "globalMetadata": {
      "_appName": "T3000",
      "_appTitle": "T3000 Documentation",
      "_appFooter": "Temco Controls · T3000 documentation",
      "_appLogoPath": "logo.svg",
      "_appFaviconPath": "favicon.ico",
      "_enableSearch": "true",
      "_disableContribution": "false",
      "_gitContribute": { "repo": "https://github.com/temcocontrols/T3000Webview", "branch": "feature/lvgl-svg-renderer" },
      "_gitUrlPattern": "github",
      "_lang": "en"
    },
    "fileMetadata": {
      "_noindex": {
        "legacy/**": false,
        "design/**": true,
        "help/**": true
      },
      "pdf": {
        "legacy/**": false,
        "design/**": false
      }
    },
    "markdownEngineProperties": {
      "markdigExtensions": ["FootNotes", "TaskLists", "Tables", "AutoIdentifiers"]
    },
    "rules": { "InvalidHref": "warning" },
    "sitemap": { "baseUrl": "https://<docs-host>/docs", "changefreq": "weekly", "priority": 0.5 },
    "disableGitFeatures": false,
    "xref": []
  }
}
```

Decisions behind the parts that matter:

| Setting | Why this value |
|---|---|
| `content` per area with `src: "."` | keeps the on-disk path as the URL path; no renaming, no moving |
| `design/**/*.md` + `help/*.md` in content | the design package is published as a **Contributing** area, but `_noindex` keeps it out of search results for users |
| `resource` globs include zip/pdf | the offline package and the PDF are downloadable from the site itself |
| `template` order | `default` (base) → `modern` (Learn-style layout) → `templates/t3000` (ours, last wins) |
| `globalMetadata._gitContribute` | powers "Edit this page" / "View source" links without any per-page metadata |
| `fileMetadata.pdf` | excludes engineering areas from the PDF (see `07-offline-pdf-chm.md`) |
| `rules.InvalidHref: warning` | broken links must be visible; blocking is done by our own gate with a baseline (`11-review-and-cicd.md`) |
| `disableGitFeatures: false` | "Edit this page" and last-modified need git; set `true` only if a huge repo makes the build slow |
| no `metadata` section | `docfx metadata` is .NET-only; API pages here are authored Markdown |
| no page `uid`s | avoids per-page front matter; cross-page links are relative `.md` links (DocFX validates them) |

### What we deliberately do **not** use

| Feature | Why not |
|---|---|
| YAML front matter in shipped pages | the no-page-metadata rule; all of it is expressed with `globalMetadata` + `fileMetadata` + `toc.yml` |
| `uid` / `xref:` in shipped pages | would require `uid:` metadata on every page |
| `docfx metadata` (API generation) | the codebase is C++/Rust/TypeScript; API pages are Markdown |
| remote `xref` maps | they need the network and would break the offline rule |

## 2. URL map

DocFX uses "ugly URLs": the file path plus `.html`.

| Source file | Generated URL | Public URL (served under `/docs/`) |
|---|---|---|
| `docs/index.md` | `/index.html` | `/docs/` |
| `docs/t3000/quick-start/overview.md` | `/t3000/quick-start/overview.html` | `/docs/t3000/quick-start/overview.html` |
| `docs/legacy/implementations/…/X.md` | `/legacy/implementations/…/X.html` | `/docs/legacy/implementations/…/X.html` |
| `docs/design/help-platform/01-plan.md` | `/design/help-platform/01-plan.html` | `/docs/design/help-platform/01-plan.html` |
| `docs/t3000/media/run.png` (resource) | `/t3000/media/run.png` | unchanged |

Because the site is served under the **same `/docs/` prefix** the app and the MCP tools already use, every
existing path keeps its meaning — only the `.html` suffix is new for humans. Two options for the host:

- **Preferred**: serve `_site` at `/docs/` with a rewrite that appends `.html` for extensionless paths.
  Then `…/docs/t3000/quick-start/overview` (the form people paste) resolves too.
- **Fallback**: serve the site at `/learn/` and let `/docs/…` keep returning raw Markdown, as it does
  today for the app.

Images and other resources are copied verbatim, so the relative image paths already used inside pages
(`media/x.png`, `../images/y.png`) keep working.

## 3. `toc.yml` files

DocFX reads TOC as YAML. Node properties: `name`, `href`, `items`, `uid`, `expanded`; a TOC can also
carry `order` (which TOC wins when several reference the same article) and `pdf:` (PDF on/off).

### `docs/toc.yml` — the top navigation bar

The `toc.yml` beside `docfx.json` becomes the site's top navigation. It uses **reference TOCs**
(`href: folder/`) so each area keeps its own generated tree:

```yaml
# generated by scripts/docs-registry.mjs — do not edit
items:
- name: Home
  href: index.md
- name: T3000
  href: t3000/
- name: Design Studio
  href: t3000/t3-eez-studio/
- name: Protocols
  href: t3000/building-platform/
- name: API
  href: t3000/api-reference/
- name: Legacy / Engineering
  href: legacy/
- name: Contributing
  href: design/
- name: Release Notes
  href: t3000/releases/
```

### `docs/t3000/toc.yml` — the left navigation for an area

```yaml
# generated by scripts/docs-registry.mjs — do not edit
order: 0
items:
- name: Getting Started
  href: quick-start/toc.yml          # nested TOC (children render inline)
- name: Device Management
  href: device-management/toc.yml
- name: Data Points
  href: data-points/toc.yml
- name: Features
  href: features/toc.yml
- name: Building Platform
  href: building-platform/toc.yml
- name: API Reference
  href: api-reference/toc.yml
- name: Guides
  href: guides/toc.yml
- name: Release Notes
  href: releases/toc.yml
```

Rules the generator follows (all from `registry.json`):

| Rule | Source |
|---|---|
| Node order | `chapter` order, then `order` inside the chapter |
| Node name | `title` (never derived from the file name) |
| Leaves | `href: <path>.md` for each `ship: true` page |
| Chapters with one page | no intermediate folder node |
| Areas | one root `toc.yml` per published area: `t3000`, `legacy`, `design` |
| Not published | pages with `ship: false` are absent from every TOC (they exist only in the registry) |
| `expanded` | `true` on the first two levels so the tree arrives open, matching the in-app page |

### `docs/toc.pdf.yml` — the PDF-only TOC (phase 4)

```yaml
order: 200            # keeps it out of the site navigation
pdf: true
pdfFileName: T3000-Learn.pdf
pdfCoverPage: cover.html
pdfTocPage: true
items:
- name: Getting Started
  href: t3000/quick-start/toc.yml
- name: Device Management
  href: t3000/device-management/toc.yml
# ... user-facing areas only; legacy/ and design/ are excluded
```

## 4. Generation and parity

`scripts/docs-registry.mjs` writes, from one registry read:

```
docs/docfx.json                 docs/toc.yml
docs/t3000/toc.yml              docs/legacy/toc.yml        docs/design/toc.yml
docs/help/manual.json           docs/help/reference.json   docs/help/engineering.json   (CHM manifests)
docs/help/index.json            docs/help/page-meta.json   docs/help/versions.json
```

Two assertions run in CI (`npm run docs:registry --check`):

1. **Freshness** — regenerating produces the byte-identical files already committed.
2. **Parity** — the page set in `toc.yml` equals the page set in the CHM collection manifests. A page in
   one and not the other fails the build with both paths printed (this is what stops the site and the
   shipped help file from drifting apart).

6. Record the URL map above in the docs-owner runbook; decide the host prefix (`/docs/` preferred).

**Acceptance:** `npm run docs:registry --check` is clean; `npm run docs:site` produces `_site/toc.html`,
`_site/t3000/toc.html`, `_site/legacy/toc.html`, `_site/design/toc.html`; every `ship: true` page has a
TOC entry; deleting one page from the registry makes the parity check fail.
